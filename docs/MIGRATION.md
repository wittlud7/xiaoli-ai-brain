# 从 v0.1 升级与数据恢复

## 正常升级

1. 升级前，在旧版导出一份 JSON 工作区备份；旧音频另行下载。
2. 更新代码、执行 `npm ci` 并启动新服务。
3. 使用与旧版相同的浏览器、域名和端口打开。新版首次创建 IndexedDB 工作区时，会读取旧 `xiaoli-workspace-v1`；也兼容更早的三个静态版存储键。
4. 成功迁移后检查资料和历史，再从新版导出一份备份。旧 localStorage 不会被自动清理。

若换了浏览器或端口，在“数据与设置”导入旧备份。导入前会校验数据，并再次确认；校验失败或用户取消时不会替换当前工作区。

## 保留与变化

- 保留资料正文、笔记本、关联和可用的文字历史。旧的长标题、名称与播客全文不会为满足新界面限制而截断。
- 旧版摘要和 Markdown 导图提纲作为“旧版记录”保留，不伪造新的原文引用；可导出全文。旧记录需重新生成后才能使用带来源版本检查的追问。
- 旧预设图谱的掌握标记不转换为真实概念掌握度，因为二者并不是同一组概念。
- 旧版音频没有进入工作区 JSON，无法通过 JSON 迁移；新音频保存在 IndexedDB，刷新后可重新播放。
- 旧静态版部分 PDF 只有占位文字，原 PDF 从未存入浏览器，无法凭空恢复。界面会提示重新导入原文件，并阻止使用这些占位记录生成。
- 音频与脚本版本绑定。导入改变了脚本的备份时，不会错误复用旧音频。

## 存储失败或冲突

保存先经过校验，再通过 IndexedDB 事务写入。空间不足或写入失败时，原提交数据保留；笔记编辑窗口会保留草稿，可清理空间后重试。

多标签页使用版本号比较。若另一个标签先完成保存，陈旧写入会被拒绝，当前页面载入最新数据并提示重试，不自动覆盖别人的修改。正常提交还会通知其他页面刷新。

不要同时在多个窗口导入整份备份；这是一项明确的工作区替换操作。JSON 中不包含音频，需要时分别下载。

## 损坏数据

发现无效旧数据或损坏的 IndexedDB 时，新版不会自动用空工作区覆盖。错误页面提供“下载原始恢复文件”，包含可读取的原始工作区和指定旧存储键，不包含访问口令。

恢复文件供排查和人工修复使用，不是可直接导入的标准备份。错误页面另有“从有效备份恢复”：校验并再次确认后，才用已知有效的 JSON 备份替换损坏记录；保留旧 localStorage 和音频数据，不会自行清空浏览器。若需人工协助，先去除私人资料，不要把原始恢复文件直接上传公开 Issue。

若浏览器完全拒绝存储访问，可能无法读取 IndexedDB。此时先检查站点权限、隐私模式和剩余空间，不要立即清除站点数据。
